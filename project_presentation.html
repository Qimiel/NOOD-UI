Runtime Pipeline
03 / 13

Stage responsibilities

1. Input and intent

The loader discovers frames from a file, folder, or video. The selector interprets user intent through text, bbox, point, or auto foreground mode.

\( \texttt{path} \rightarrow \{I_i, t_i, \mathrm{metadata}_i\}_{i=1}^{N} \)

2. Mask and view prep

SAM2 or rembg creates object masks. The preprocessor crops, pads, centers, and writes RGBA object views for reconstruction.

\( (I_i, M_i) \rightarrow V_i = \mathrm{resize}(\mathrm{crop}_{M_i}(I_i)) \)

3. Reconstruct and report

The NeRF backend produces geometry and appearance; postprocess normalizes and cleans the result; the exporter writes GLB/OBJ and a JSON report.

\( V^\star \rightarrow (\mathcal{M}, \mathcal{T}) \rightarrow \texttt{asset.glb} \)
Each stage emits typed contracts rather than loose path conventions. Debug output: frames, masks, crops, backend logs, mesh

Typed contracts keep stages replaceable

Input, selection, segmentation, view preparation, reconstruction, mesh cleanup, and export exchange explicit dataclasses.

ObjectCandidate

Target bbox, label, selection confidence, and frame id.

ObjectView

RGBA crop, mask path, bbox, source frame, and quality metrics.

ReconstructionResult

Mesh path, texture paths, backend name, runtime, stats, warnings.

Report

Status, selected/rejected views, backend metadata, score, artifacts.

The NeRF backend is exposed through register_backend(). GUI and CLI share the same pipeline API.
NeRF Backend
05 / 13

A NeRF neural network turns selected views into geometry

The backend trains or evaluates a neural radiance field \(F_\theta\), renders novel views through differentiable volume integration, and extracts a mesh for export.

\[ B_{\mathrm{NeRF}} : \{V_i,\Pi_i\}_{i=1}^{m} \mapsto F_\theta \mapsto \left(\mathcal{M}, \mathcal{T}, s\right) \]
The backend is a NeRF-style neural radiance field. Textures and geometry are inferred from the learned field.
NeRF Concept
06 / 13

A NeRF is a continuous radiance field

Instead of storing triangles, a neural network represents color and density at every 3D location, conditioned on viewing direction.

\[ F_\theta\big(\gamma(\mathbf{x}), \gamma(\mathbf{d})\big) = \left(\sigma, \mathbf{c}\right) \]

Here \(\mathbf{x}\in\mathbb{R}^3\) is a point in space, \(\mathbf{d}\in\mathbb{S}^2\) is a camera ray direction, \(\sigma\) is volume density, and \(\mathbf{c}\in[0,1]^3\) is emitted color.

NeRF stores a function, not an explicit mesh. Meshes can later be extracted from density with marching cubes.
NeRF Rendering Math
07 / 13

Volume rendering turns density into pixel color

Continuous form

\[ \mathbf{C}(\mathbf{r}) = \int_{t_n}^{t_f} T(t)\,\sigma(\mathbf{r}(t))\,\mathbf{c}(\mathbf{r}(t),\mathbf{d})\,dt \] \[ T(t)=\exp\left(-\int_{t_n}^{t}\sigma(\mathbf{r}(s))\,ds\right) \]

Transmittance \(T(t)\) is the probability that the ray reaches depth \(t\) without being absorbed.

Training and rendering evaluate a finite set of points along each camera ray, then alpha-composite their colors front to back.

Positional encoding

Raw coordinates are lifted into high-frequency sinusoids so the MLP can represent sharp spatial variation:

\[ \gamma(p)= \left(\sin(2^0\pi p),\cos(2^0\pi p),\ldots, \sin(2^{L-1}\pi p),\cos(2^{L-1}\pi p)\right) \]
The image is differentiable with respect to field parameters \(\theta\). That makes training direct photometric optimization.
NeRF Training
08 / 13

Training optimizes rendered pixels

The network is trained from calibrated images. Each batch samples camera rays, predicts color through volume rendering, and backpropagates image error.

\[ \mathcal{L}(\theta)= \sum_{\mathbf{r}\in\mathcal{R}} \left\| \hat{\mathbf{C}}_\theta(\mathbf{r})-\mathbf{C}_{gt}(\mathbf{r}) \right\|_2^2 \]
  • Inputs need camera poses and intrinsics.
  • Training samples many rays instead of full images.
  • Regularization and coarse-to-fine sampling improve stability.
  • Mesh export usually thresholds density and runs marching cubes.
The NeRF backend estimates or receives camera assumptions for selected views. Training quality depends on pose accuracy, coverage, and object masks.

Summary
13 / 13

Core takeaways

  • The project is a staged, typed scene-to-asset pipeline.
  • Segmentation and view filtering protect the backend from bad crops.
  • The NeRF neural-network backend sits behind a small protocol.
  • Reports make uncertainty explicit: confidence, warnings, mesh stats, texture caveats.
  • NeRF is the volumetric backend: differentiable rendering plus photometric training.

Where NeRF fits

The NeRF backend consumes selected views with camera estimates, optimizes a field \(F_\theta\), extracts a mesh, then hands the result to the existing postprocess and export stages.

\[ \text{views} + \text{poses} \rightarrow F_\theta \rightarrow \mathcal{M} \rightarrow \texttt{asset.glb} \]
